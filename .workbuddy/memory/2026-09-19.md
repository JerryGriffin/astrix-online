## v0.0.94（已发布，3 分钟内那两条）
- 离线文案：面板写死「1/10」而实际 v0.0.91 起已是 1/4。修法：state.js 导出 **`OFFLINE_RATIO = 0.25`**，
  main.js 的结算面板文案由 `1/' + Math.round(1/OFFLINE_RATIO)` 生成 → 以后改系数不会再说明失真。
- 幸福度死循环（重点）：
  - 根因1：温饱比 `supplyRatio` 取「当秒最紧缺营养的 have/want」，库存某一秒略低于当秒需求就 <1，
    幸福度开掉；人口掉→产出少→更容易不够 → 越滚越低。
    修法：**本 tick 扣粮之前**判断 `fed = 三种营养都 > 0` → fed 则 `supplyRatio = 1`。
    ⚠ 判定时机很关键：放在扣粮之后会把「刚吃完最后一口」误判成断粮。
  - 根因2：母星也会被抖动拖下去。修法：`state.js` 传 `homePlanet: !!inst.isHome`，
    `population.js` 里 `target = (homePlanet && fed) ? max(rawTarget, HOME_HAPPINESS_FLOOR=0.88) : rawTarget`
    —— **只在还有食物时保底**，真断粮照样掉（否则玩家看不到问题）。
  - 实测：食物充足 300s 母星稳 0.900；断粮 200s 掉到 0.380；恢复供粮 300s 回到 0.899。
- 云服务按用户要求暂不动（环境已激活，凭据见上一条）。
