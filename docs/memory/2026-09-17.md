## Astrix v0.0.2 设计阶段

延续 v0.0.1（已发布 https://astrix.app.workbuddy.host/）。今天主要做设计对齐，代码改动由子代理并行进行。

### 用户新确认的规则（重要，后续版本必须遵守）
- **时间**：现实 1 秒 = 游戏 1 秒（实时制）
- **货币**：Ascoin 是星际通用货币，**1048576 Ascoin 恒等于 1 金**（2^20）；
  **镒 Eridium 是稀有货币，没有固定汇率**，不能与 Ascoin/金 互相兑换，只单独计数
- **建筑造价**：**纯材料**计价，不用 Ascoin
- **元素**：铱 Ir 保留；新增虚构元素**镒 Eridium**（符号建议 Ed）作高级货币；新增**锰 Mn**
- **金属一律以原矿呈现**（铁→赤铁矿、铜→孔雀石、锌→闪锌矿、铝→铝土矿、钛→**金红石**、
  银→粗银、金→粗金、钨→黑钨矿、锂→锂辉石、锰→软锰矿、铀→沥青铀矿、铱→铱铂矿）
- **氨只以气态存在**，不从地表刷新（与 Astroneer 不同）
- **不引入 Astroneer 的星门**，也不要擅自添加 Astroneer 其它内容
- **只有希尔瓦有人力**（1k 总/900 可用），其余 6 个星球开局 0 人力，只能从希尔瓦移民
- **新增建筑「人力发电厂」，开局即解锁** —— 这是为了解决「科研所耗电 50 但开局没发电厂」的死锁。
  每工位 10 电/秒 × 6 工位 = 60 电/秒，刚好供得起科研所
- 建筑数量：18 个（原 12 + 精细加工厂 + 火力发电厂 + 综合燃烧室 + 清洁发电厂 + 大气收集器 + 人力发电厂）

### 已修的两个真 bug（本轮我自己动手修的，子代理撞 429 频率限制不可用）
1. **进度根本不落盘**（用户报的「离线模式存档选择还有问题」的根因）：
   `saveState()` 只写账号，星球实例（inventory 全在里面）从不持久化 → 刷新即归零。
   修法：新增 `PLANETS_KEY = 'astrix.save.planets.'`，星球实例**按账号分别**存；
   `switchAccount` 先存旧账号再载入新账号（避免存档串数据）；`deleteAccount` 同时删星球键。
2. **游戏循环只挂在物品栏里**：tick 只在物品栏 tab 开着时才跑，切走就停。
   修法：main.js 加全局 1 秒心跳 `startLoop()`，物品栏定时器改为只刷新显示不再调 tick（否则双重计时）；
   `tick()` 内置每 10 秒自动存档；`beforeunload` 强制落盘一次。
   验证：模拟刷新往返测试 PASS（tick60 后重载数量完全一致）。

3. **子代理误报导致建筑造价被改坏**：它读旧版 materials.js 判定缺 石头/木头/泥土/水，
   于是把造价替换成 粘土/有机质/土壤（还出现 `{有机质:200, 土壤:100, 有机质:50}` 重复键丢数据）。
   实际这四个材料一直都在。已逐条还原 18 个建筑的 baseCost。
   **教训：子代理报告「某某不存在」时要自己复核，别信。**

### 挖出并修掉的设计缺陷（关键，后续别踩）
**建材可获得性铁律**：建筑只能用「解锁它的科技层级或更低」的材料，否则死锁。
用户给的初版造价违反了 3 条，加上熔炉耗电，一共 4 处死锁：
1. 科研所要「石英+铜」（石英需 A1、铜需 B2）→ 改纯 T0 材料（石头/泥土/有机质）
2. 建造车间要「铁+粘土」→ 改纯 T0
3. 人力发电厂要「木头」（木头只能熔炉产、熔炉要研究点、研究点要科研所供电）→ 改用有机质
4. 熔炉耗电 20 → 改为 **0**（燃烧自身放热），否则「熔炉↔人力发电厂↔木头」闭环
5. 船坞要「钛」（钛来自电解池，电解池前置是船坞）→ 自指，改用铁+钢
6. 农田要「塑料」、大气收集器/修理厂要「橡胶」、清洁发电厂要「塑料」→ 都属 T4，降级替换

### 本轮挖出并修掉的 3 个真 bug（都是自检抓的）
1. **稳态温度牛顿迭代符号写反** → 新船出厂温度 **1.56 亿 K**，船员瞬间全灭、永远起飞不了。
   根因：`net = qGen + qEnv − qRad`，qEnv 与 qRad 都随 T 上升，故 `dnet/dT < 0`；
   代码算出的 `dQdT` 是绝对值却用了 `T -= net/dQdT`。改为 `T += net/dQdT` + [3,5000] K 兜底。
2. **`emptyBlueprint()` 的外壳 id 漏型号后缀**：写的是 `hull_s`，真实 id 是 `hull_s_mk1`，
   `resolvePart` 返回 null → 一打开蓝图编辑器就报「容量不足 30/0」。已修，并加了
   「蓝图部件的 id 必须存在于 PART_BY_ID」的自检断言。
3. 施工硬门槛与人力发电厂造价：见上。

## 发布后修正：增速显示「看不见变化」（版本仍为 v0.0.6）

用户反馈：「增速提升到小数点后四位，不然 0.0 看不见变化，**版本不变**」。

### 诊断过程（关键：先别猜，去看线上跑的是什么）
1. 先怀疑 `fmtRate` 精度不够 —— **错的**。我直接抓了线上
   `https://astrix.app.workbuddy.host/js/core/format.js?v=0.0.6`，
   确认线上就是 `trimZeros(v.toFixed(4))`，四位数早就有了。
2. 全仓 `grep` 所有「速率显示」位置，找到真因 —— **两处，不在 `fmtRate`**：
   - `js/ui/power.js:106/108`：总发电 / 总耗电写的是 **`fmtNum(pw.gen) + '/s'`**。
     `fmtNum` 对小数走 `toFixed(1)` → 发电量 < 0.05 就是 **`0.0/s`**。
     **这就是用户看到的「0.0」。**
   - `js/ui/buildings.js`：施工速度 `fmtNum(rate*60)`、产出速度 `perMin.toFixed(1)`
     与 `(outputs[k]*60).toFixed(1)` —— 同样是 1 位小数。
3. 另有一个隐患：**四位小数会把 < 5e-5 的值四舍五入成 0.0000**，
   显示成「+0/s」。粗金这类丰度 1e-7 的资源就落在这一档。实测确认：
   修复前 `0.00002 → +0/s`、`1e-7 → +0/s`。

### 修法（版本号不变，但要能击穿缓存）
- `js/core/format.js`：新增导出 **`fmtRateBody(n)`**（只取数字体，不带 `+/-` 与 `/s`），
  `fmtRate` 改为复用它。精度三档：`>=1e3` 走 fmtNum 的 k/m/g；`1e-4 ~ 1e3` 固定 4 位去尾零；
  **`0 < v < 1e-4` 改用科学记数法**（`1e-7` 也必须看得出不是 0）。
- `js/ui/power.js`：总发电 / 总耗电改用 `fmtRate`，燃料消耗改用 `fmtRateBody`。
- `js/ui/buildings.js`：三处速率改用 `fmtRateBody`。
- **`js/version.js` 新增 `REVISION` 与 `CACHE_TAG = VERSION_NUM + '.' + REVISION`**，
  index.html 的 `?v=` 改用 `CACHE_TAG`（现为 `60.1`）。
  这一条很重要：用户说「版本不变」，但缓存击穿串**必须**变，否则浏览器继续吃旧文件、
  用户会以为改动没生效。以后遇到「版本不变」类需求一律靠 `REVISION` +1。
- `docs/selfcheck_v005.mjs`：缓存击穿断言改用 `V.CACHE_TAG`，并新增「6 个 css 链接都要带同一个串」。
- `docs/selfcheck_v006.mjs`：新增 **F 组（19 项）**——逐值断言精度、断言非零小速率不得显示成 0、
  并**扫 `js/ui/*.js` 源码**禁止再出现 `fmtNum(...) + '/s'` 与 `.toFixed(1) + '/分钟'`（防回归）。

## v0.0.61 修订 1（版本不变，CACHE_TAG 61.0 → 61.1）

用户两条：「飞船蓝图根据部件等级来确认 mk 等级；修复 bug 物品栏中的增速仍然只有小数点后一位，版本不变」。

### 1. 飞船 MK 由部件等级决定
`js/core/shipyard.js#evaluateBlueprint`：
```js
const mark = Math.max(...[hull, ...engines, ...parts].filter(Boolean).map(p => p.mark));
const markLabel = (MARKS.find(m => m.mark === mark) || MARKS[0]).label;
```
原来是 `hull ? hull.mark : 1` —— **只看外壳**。改为取**全部已装部件里最高的一档**
（引擎/武器/设施用了更高档，整船就判定为那一档，避免「装了高档引擎却判定为基础档」）。
新增 `MARKS` 导入。飞船详情（`js/ui/shipyard.js`）加了「MK 等级」一行显式展示 ——
否则蓝图换了更高档部件，界面上毫无反馈，等于没做。
（目前部件只有基础一档，所以恒为 1；机制已不依赖外壳，日后加高档部件自动生效。）

### 2. 「增速仍然只有小数点后一位」的真根因（这次没猜错方向）
先验证代码：`inventory.js` 走的就是 `fmtRate`，全仓 `toFixed(1)` 里**没有** inventory.js。
所以不是 1 位小数代码路径。

真正原因：**尾零被抹掉**。之前 `fmtRateBody` 是 `trimZeros(v.toFixed(4))`，
而人口呼吸消耗恰好是 **0.2/s 这种整数值** → `0.2000` 被抹成 `0.2` →
玩家看到的氧气/有机质/水全是 `-0.2/s`，自然觉得「只有一位小数」。

改法：**不再去尾零**。
```
v >= 1e3        → fmtNum 的 k/m/g（2.5k）
非整数          → v.toFixed(4)，**不抹尾零**（0.2000 / 0.6250 / 1.0125 / 0.0010）
0 < v < 1e-4    → 科学记数法（1e-7）
整数 / 0        → 240 / 0
```
⚠ 这是**同一个坑的第二次**：
- 第一次（v0.0.53 之前）：只保留 1 位，0.0523 被显示成「+0.1」；
- 第二次（v0.0.61）：保留 4 位但**抹尾零**，0.2000 被显示成「0.2」。
两次都是「玩家说看不出变化 / 只有一位」，但根因完全不同。已在 MEMORY.md 记死。
