> 这份文档是给设计者过目用的：营养代谢、工位模型、幸福度公式与人口增长，全部在此列清。
> 代码位置：核心逻辑 `js/core/population.js`，面板 `js/ui/population.js`，

## 一、三个数字（别再混了）

| 概念 | 字段 | 定义 | 希尔瓦开局 |
|---|---|---|---|
| **总人数** | `pop.total` | 星球上的总人口 | 1000 |
| **总人力** | `getTotalLabor(pop)` | `floor(总人数 × 劳动参与率)`，参与率 0.9 | 900 |
| **可用人力** | `getAvailable(pop)` | `floor(总人力 × 幸福度) − 已分配人力` | 900×0.9 − 0 = **810** |

面板顶部四个大数字显示的是：总人数 / 总人力 / 可用人力 / 幸福度。

## 二、营养代谢：一吃五出（v0.0.5 新规则）

**休息状态**下，每人每秒（v0.0.52：数值由 0.01 改小为 0.002，整体降低 5 倍）：

| 方向 | 资源 | 数量 |
|---|---|---|
| 消耗 | 氧气 | 0.002 |
| 消耗 | 有机质 | 0.002 |
| 消耗 | 水 | 0.002 |
| 产出 | 二氧化碳 | 0.002 |
| 产出 | 甲烷 | 1e-4 |
| 产出 | 氨气 | 1e-4 |

工作强度在**休息基数上同时放大消耗与产出**（代谢越旺，吃得多也排得多）：

| 档位 | 强度 | 消耗倍率 | 产出倍率 |
|---|---|---|---|
| 休息 | 0 | ×1.0 | ×0 |
| 轻度 | 0.5 | ×1.5 | ×0.5 |
| 标准 | 1.0 | ×2.0 | ×1.0 |
| 高强度 | 1.5 | ×3.0 | ×1.5 |
| 极限 | 2.0 | ×4.5 | ×2.0 |

计算公式（`consumptionPerSec` / `metabolitePerSec`）：

```
消耗[k] = 总人数 × 0.01
        + Σ_职业 (该职业人数 × 0.01 × (该职业消耗倍率 − 1))
产出[k] = 总人数 × 基数
        + Σ_职业 (该职业人数 × 基数 × (该职业产出倍率 − 1))
```

> 例：1000 人 + 40 个建筑工（极限档）
> 耗水 = 1000×0.01 + 40×0.01×(4.5−1) = 10 + 1.4 = **11.4/s**
> 产甲烷 = 1000×5e-4 + 40×5e-4×3.5 = 0.5 + 0.07 = **0.57/s**

**进食比例**：三项营养里**最紧缺的那条**决定实际进食比例 `ratio`；
只按 `ratio` 扣料，代谢产物也按 `ratio` 折算（吃不饱就少排）。

## 三、工位模型（v0.0.5 改为按建筑算）

```
某建筑的空闲工位 = 建筑数 × 每座工位数 − 该建筑下已指派人数
```

- 一座建筑下的**多个职业共用一个工位池**。例：制造车间有「小型物件工」「中型物件工」两个职业，
  1 座制造车间提供 28 个工位，两个职业加起来最多 28 人 —— 于是**多个人可以在一个建筑里从事不同的工作**。
- 一次分配同时受**可用人力**与**建筑空闲工位**双重夹取，取小者。
- 建筑工位表：建筑工厂 40 · 科研所 32 · 制造车间 28 · 船坞 120 …
  （完整数据见 `docs/buildings.md`，字段名 `jobs`）

### 岗位可见性（只显示能分配的）

| 情况 | 面板表现 |
|---|---|
| 岗位不需要建筑（如地表采集工） | 永远显示，归入「无需建筑」分组 |
| 岗位对应建筑已建成（数量 > 0） | 显示，并给出该建筑的工位 / 已指派 / 空闲工位 |
| 岗位对应建筑未建成 / 科技未解锁 | **一律不渲染**，底部一行提示「另有 N 个岗位…」 |

> 开局只有 1 座建筑工厂，所以人力面板只有两行：「无需建筑」的地表采集工 + 建筑工厂的建筑工。
> 把建筑造出来，岗位就会自己出现。

### 分配方式

每行：`−` / 数字输入栏 / `＋` / 满员 / 工作强度下拉。
输入栏（`input.cnt-in`，`type=number`）支持一次填几百人，**回车即生效**，不用点几百次 `＋`。

## 四、幸福度公式（v0.0.4 定稿，v0.0.5 沿用）

```
H = 0.40                      基准（活着就有）
  + 0.35 × S                  温饱项   S = 实际供给 / 实际需求（0~1）
  − 0.30 × (1 − S)            饥饿惩罚
  + 0.15 × C                  庇护项   C = 庇护覆盖率（v0.0.51 起由建筑提供，见第五节）
  − 0.50 × max(0, W−0.60)/0.40 过劳项  W = 已分配人力 / 总人力
  − 0.40 × min(1, |T−293|/40)  温度项  T 为环境温度（K），293 K = 20 ℃ 舒适

H = clamp(H, 0, 1)
```

各项系数都在 `js/core/population.js` 顶部常量区，**改一个数就能调平衡**：

| 常量 | 值 | 含义 |
|---|---|---|
| `HAPPINESS_BASE` | 0.40 | 基准项 |
| `HAPPINESS_FOOD_MAX` | 0.35 | 温饱项上限 |
| `HUNGER_PENALTY_MAX` | 0.30 | 饥饿惩罚上限 |
| `HAPPINESS_SHELTER_MAX` | 0.15 | 庇护项上限 |
| `OVERWORK_COMFORT` | 0.60 | 工作占比 ≤ 此值不惩罚 |
| `OVERWORK_PENALTY` | 0.50 | 过劳惩罚上限（100% 上班时扣满） |
| `HAPPINESS_TEMP_MAX` | 0.40 | 温度项上限 |
| `COMFORT_TEMP_K` | 293 | 舒适温度 |
| `TEMP_TOLERANCE_K` | 40 | 偏离 40 K 扣满 |
| `HAPPINESS_RECOVER` | 0.02 | 逼近目标值的速度（时间常数 50 秒） |

### 自校验

吃饱（S=1）+ 有庇护（C=1）+ 20 ℃ + 不过劳（W≤0.6）：

```
H = 0.40 + 0.35 − 0 + 0.15 − 0 − 0 = 0.90
```

正好对上希尔瓦开局的 **1000 总人数 / 900 总人力**（幸福度 0.9 → 可用人力 810）。
这条校验写进了 `docs/selfcheck_v005.mjs`，改公式就会立刻报出来。

### 时间行为

幸福度不是瞬间跳到目标值，而是以 `HAPPINESS_RECOVER × dt` 的比例逼近，
避免「刚断粮幸福度立刻归零」这种跳变；断粮后会持续下滑。

## 五、庇护（v0.0.51 起生效）

`C = 总庇护 / 总人数`，夹取到 [0,1]。总庇护 = Σ(建筑座数 × 该建筑每栋的 `shelter`)，
目前只有**房屋**提供（100/栋），开局自带 **5 座 = 500 庇护**，希尔瓦 1000 人时 **C = 0.5**。

| 庇护率 | 幸福度（吃饱 + 20 ℃ + 不过劳） |
|---|---|
| C = 1（住房充足） | **0.90** |
| C = 0.5（开局） | **0.825** |
| C = 0（无家可归） | **0.75** |

> 关键：v0.0.5 时 `advancePopulation()` **根本没把 shelter 传进来**，庇护项恒为 1，
> 房屋这类建筑完全不起作用。v0.0.51 才真正接上。

## 六、人口增长 / 下降

v0.0.52 起改为**连续生育率**，不再是「过了阈值才变」的硬跳变：

```
生育率 f = (H − 0.5) / 0.5        ∈ [−1, +1]
人口变化 = total × (f ≥ 0 ? f × GROWTH_RATE : f × DECLINE_RATE) × dt
```

| 幸福度 | 生育率 f | 行为 |
|---|---|---|
| 1.0 | +1.0 | 满速增长 |
| 0.9 | +0.8 | 增长 |
| **0.5** | **0** | **持平（平衡点）** |
| 0.4 | −0.2 | **倒扣** |
| 0.0 | −1.0 | 满速衰减（速度是满速增长的两倍） |

跌破 0.5 就开始减少，不用再等到 0.3。这是一个自平衡：
人口涨 → 庇护率降 → 幸福度降 → 增长放缓 → 停在某个平衡点。

实测（自检第二十三节会打印，1 小时）：

| 场景 | 幸福度 | 1 小时后 |
|---|---|---|
| 满庇护 + 吃饱 | 0.90 | **+9.0%** |
| 无庇护 + 吃饱 | 0.75 | **+5.6%**（明显放缓） |
| 断粮 | 0.25 | **−9.9%**（倒扣） |

> v0.0.51 把速率调慢了约 100 倍。旧值 `GROWTH_RATE = 0.005` 看着小得可怜，
> 但它是「每秒」的复合增长率：幸福度 0.9 时每秒 +0.2%，挂机一小时就是 **1339 倍**，
> 人几秒钟翻一番。新值按「每小时」设计（见上表实测）。

## 七、施工硬门槛（与人力联动）

```
施工速度 = 建筑工厂工位上的「建筑工」人数 × WORK_PER_SEC
```

- **没有建筑工厂，或建筑工厂里没人当建筑工 → 施工速度恒为 0**，施工队列一动不动。
- 这不是「加快施工」，而是「**没它就不能施工**」。
- 施工量与工位封顶（多派的人不产生施工量）。
- 取消施工**全额退还材料**。

船坞同理：**没有分配「船坞工」就组装不出飞船**（`shipBuildBlockReason`），
面板会直接给出「请到人力面板派船坞工」的提示。
